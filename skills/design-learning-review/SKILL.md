# 设计学习与弹性评审

目标是帮助用户完成真实任务，用足够的证据作出相称的设计判断。它是判断指南，不是自动执行脚本，不要求产品采用向导，也不要求每次运行完整评审。

## 先确定任务，再决定评审深度

尊重用户指令、项目约束和既有授权；本 Skill 不授予实现、文件写入、外部传输、安装或上线权限。项目只读/交接规则仍有效。已授权的正常工作不重复请示。

从已有材料提取用户目标、使用者、现有入口和能力、保留/新增/修改内容及验收边界。只追问会改变结论的缺口，其余标明假设并推进。不把未知当作不存在。

先区分独立操作、真实前置依赖、可选分支和状态，再确定入口、主次、分组、布局及视觉。不要因文字列举顺序、编号或相邻位置推导操作顺序；不要为美观删掉已有入口。

按影响、证据缺口和失败后果选择最小充分检查，允许途中增减：
- 局部间距等低影响且关系不变的调整：核对相关布局、可读性和受影响状态，直接给结论。
- 入口、操作关系或多状态变化：走查关键任务和受影响分支，核对现状与方案；需要时查看原型或运行界面。
- 覆盖数据、权限、隐私或关键关系仍不确定：检查相应失败、恢复和边界条件；需要时引入独立视角与交叉证据。不能用“轻量”跳过必要检查，也不要扩展为无关全面审计。

复杂关系或争议时读 [评审方法](references/review-method.md)；选择工具或证据时读 [能力池](references/tool-pool.md)。无需默认加载全部参考资料。

重要判断应能追溯到任务目标、现状约束、变更影响、证据缺口和失败后果，区分事实与推断；工具评分不能作为独立依据。需要深入界面评审时，优先检查同级个人 Skill `impeccable-review/SKILL.md`，按需读取相关检查。它是只读适配版，不是完整官方流程；简单调整无需加载，不存在时如实说明并使用现有能力，不自动安装。专业指导不等于独立证据，实测结论必须有测量或操作记录。

## 交叉验证与收敛

只有能减少具体不确定性时才增加验证。独立价值可以来自不同原始材料、实际任务走查、用户证据、测量或真正独立的审查；多个工具复述同一输入不增加置信度。

确需独立审查且授权和环境允许时，给审查者原始任务、材料、约束和问题，尽量先不暴露主方案结论。独立代理不是默认步骤，也不凑人数。同一执行者切换角色只能称自查。无法获得所需独立证据时说明缺口，缩小结论或暂缓关键决定，不伪称已验证。

异议说明场景、依据、影响与替代方案；先核实事实和假设，再按用户目标与实际效果取舍，不按票数、职位或机械拼接决定。职责内设计和技术取舍由执行者解决；目标/范围变化、重要风险接受、证据不足且明显影响使用的分歧交用户决定。保留重要取舍和未解决分歧。

关键问题解决，且继续检查不会带来新增有效证据时停止。材料受限时也应停止无效重复，但标记待验证，不能声称通过。只有新增需求、状态、证据或实际回归才重新打开已认可结论，不因换工具重审，不顺势扩大范围。

## 交付与学习

交付量与任务相称：简单变化用短结论和必要核对；复杂变化说明关键依据、优先问题、取舍、验证范围及剩余不确定性。不机械生成报告或项目文件。项目只在执行交接或重要结论需要记录且获授权时留痕，遵守项目已有规则。

用户要求学习/沉淀或真实复盘产生可复用结论时，读 [知识记录](references/learning.md)。区分参考原则、项目经验和通用约定，记录来源、原理、适用条件、例外、正反例与检查方法。单次反馈先作为有边界的经验，不升级为普遍规则。未经授权不改个人知识或项目规则；持久文件只是以后可读取的资料，不声称模型永久学习。

查看 [案例与验证](references/cases.md) 可校准裁剪和停止边界；它们是示例，不是每次必跑的清单。

用户要求真实项目试用时，读 [试用与反馈](references/trial.md)。只审查指定范围，说明实际用了哪些能力、增加了什么发现、哪些仍未验证。试用不构成开发授权，不自动更新个人或项目规则。
