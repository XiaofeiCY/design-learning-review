# 维护与同步

## 唯一维护源

项目目录：`E:\work\design-learning-review`。远端：`https://github.com/XiaofeiCY/design-learning-review.git`。

`skills/` 是两个 Skill 的维护源，个人 `~/.codex/skills/` 下为可调用安装副本。以后先在仓库修改、验证和审阅，再按授权同步安装副本，比较内容以防覆盖个人未知改动。不要继续在旧聊天目录或 archive 内维护。仓库不会自动部署到个人目录或跨设备同步。

## 协作边界

需求讨论通常先形成任务文档，再由用户交给 Claude 实现；用户明确要求 Codex 修改、迁移或修复时，按明确授权执行。本次已授权迁移、提交和推送。尚无额外功能实现任务。

重要范围、验收、风险和执行状态及时更新 docs/status.md；具体派发文档按需存 docs/tasks/。普通问答不机械写文件。需要 Claude 执行时，先落文档再提供包含项目入口、当前快照、任务路径、范围、不做事项和验证命令的可复制提示词。

后续提交使用 `<type>: <中文描述>` 或 `<type>(<scope>): <中文描述>`。提交前检查暂存内容，不提交真实业务资料、下载缓存、重复备份或敏感信息。迁移授权不等于未来所有推送均已授权。

## 修改与复盘

保持精简入口与按需参考。对实际问题作有边界的修订，不把一次反馈升级为普遍规则。升级第三方指导先核对固定来源与指令冲突，不自动安装或运行工具，不修改业务项目规则。

验证结构、引用和授权边界；判断逻辑改变时用合成场景验证行为，必要且获允许时独立执行。报告实际增量和误报，不凭工具数量或单次对照宣称准确率提升。真实项目结论留在项目，个人技能仅沉淀脱敏且可复用的方法。
