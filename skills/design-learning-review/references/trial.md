# 真实项目试用

先读用户指定项目的入口、当前状态及对应方案，不改变项目规则。只读核对已有能力、任务关系和受影响状态，不顺势开发。

先形成必要的任务判断；存在层级、认知负担、反馈/恢复疑问时，再加载 `impeccable-review` 相关检查。同一执行者前后分析只是有无额外指导的对照，不称独立验证，也不必每次生成双份报告。

用最小篇幅给出：关键结论及证据、实际加载/运行能力、额外指导增加的发现或“未增加”、已核实问题与待验证假设、误报与停止理由。无问题的简单任务允许通过，不凑数量。

收集具体反馈：是否找到真实遗漏？建议能否采用？是否误解任务、加多余步骤、把未测试说成通过？实际使用推翻了哪些结论？以操作、截图或规则为证，无需长报告。按用户授权保存脱敏反馈；项目结论留在项目，个人知识只沉淀有适用边界的方法。一次试用不能证明普遍有效。
